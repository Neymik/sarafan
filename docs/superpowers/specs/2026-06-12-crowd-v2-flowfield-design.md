# Спека v2: выставочная карта, flow fields, диалоги, очереди, инспектор

Дата: 2026-06-12. Статус: согласована в диалоге (итерация 2 прототипа).
База: прототип v1 (ветка `proto`), спека `2026-06-12-convention-crowd-prototype-design.md`.

## Мотивация (фидбек плейтеста v1)

1. Толпа малоподвижна, «прилипает» к кластерам у POI.
2. Часть агентов стоит лицом в стену (цели за стенами, вейпоинты за углами).
3. Ручной граф вейпоинтов не нравится и плохо масштабируется на сложные карты.
4. Слухи передаются слишком легко (фоновый осмос).
5. Нет инструмента «что происходит с этим агентом».

## 1. Карта-выставка (data/map.js, новый формат)

```
MAP = { w, h,
  blocks:  [{x,y,w,h,label?}, ...],   // препятствия-прямоугольники (будки, сцена-стены)
  pois:    { key: {x, y, label, weight, service?} },
  boards:  [{x,y}],
  spawn:   {x,y},                      // главный вход (поезд)
  zones?:  только для подложки-цвета
}
```

Стены-отрезки удаляются; препятствие = блок. Коллизия агент-блок: выталкивание
из прямоугольника (ближайшая грань).

Планировка (60×44, по референсу, упрощённая): сверху зал сцены во всю ширину с
двумя проёмами; ряд мерч-стендов; 3 ряда выставочных будок ~6×4 с проходами 3 м
(продольные и поперечные); ниши туалетов слева/справа; внизу фудкорт и главный
вход; два боковых входа. ~12 POI: stage, merch×2, food, info, wc×2, photo,
autograph, стенды×3. У POI `weight` — популярность для wander-выбора.
`service` — секция 5 (фуд/мерч).

## 2. Навигация: flow fields × знание

Сетка 1×1 м (`walkable` из blocks). Два набора полей по всем POI:

- **clearField[poi]** — только топология. Пересчёт при изменении проходимости
  (закрытие двери = клетки проёма стали стенами).
- **smartField[poi]** — топология + текущая плотность (стоимость клетки
  `1 + k·density`), пересчёт всех раз в ~2 с (12 POI × ~2600 клеток — дёшево).

Агент с целью POI читает **градиент поля в своей клетке** → это вектор seek;
дальше прежний конвейер сил v1 (alignment, личная зона, уступание, PBD, стены)
без изменений. `pathfinding.js`, вейпоинты, рёбра и пер-ребёрные убеждения
удаляются.

### Знание агента (всё локальное, всё маленькое)
- `knownPois: Set<key>` — география. Поле POI доступно агенту ТОЛЬКО если POI
  в knownPois. planner стартует со всеми, wanderer ~60%, zombie 2–3.
- `jamMarks: [{x,y,r,learnedAt}]` (≤4, протухают ~30 с) — известные пробки.
- `events.concert {time, place, status, learnedAt}` — как в v1.

### Узнавание (только локальные каналы)
- **Глаза**: POI в радиусе зрения → в knownPois. Исследование = wander без
  известной цели (локальные случайные цели в ПРОХОДИМЫХ клетках) + открытие POI
  по пути. Затор впереди: 2–3 пробы плотности вдоль градиента в sightRadius.
- **Табло**: учит ТОЛЬКО своему участку — POI и текущие заторы в радиусе табло
  (jamMark агентам в радиусе). Никаких «узнал всю карту».
- **Диалог** (секция 3): передача случайного факта — запись knownPois,
  свежая jamMark или событие.
- **Телефон** (Lost, канал 3): полная карта POI (скачал план выставки) — But
  медленно и тем медленнее, чем плотнее толпа (как в v1).

### Реакция на «впереди толпа» (развилка характера, решается один раз на затор)
1. **Прорвусь** — высокий `stubborn` (новый параметр 0..1) или срочность >1:
   остаётся на clearField, ломится, собирает стресс.
2. **Обойду** — переключение на smartField на ~20 с (таймер `smartUntil`):
   активно ищет обход. (Правда о плотности оправдана: он смотрит по сторонам
   прямо сейчас.)
3. **Да ну его** — низкая важность цели + скука: POI в личный кулдаун ~60 с,
   utility перевыбирает цель.

### Lost v2
Триггер: хочет POI не из knownPois (и срочность высокая), или цель потерял.
Каналы выхода: табло (локально учит) → сосед/диалог → телефон (полный план,
медленно в толпе) → таймаут (забил). Тело стоит — пробка вокруг, как в v1.

### Паническое забывание
stress > 80 → на think-тике шанс ~5% потерять случайный POI из knownPois.
Петля: давка → паника → забыл → Lost → пробка.

## 3. Диалоги (вместо осмоса; sim/dialogue.js)

Осмос удаляется. Старт: ≥2 агента в радиусе 1.2 м, оба perception>0, не lost,
не в горящем goto (urgency<1), кулдаун ~20 с прошёл; шанс за тик ×
`sociability` (новый параметр 0..1). Активность `talk` 4–7 с: стоят, или если
шли в одну сторону (dot(v₁,v₂)>0) — идут вместе на ×0.5.

Тема = случайный факт из объединения знаний: запись knownPois / свежая jamMark /
событие. Передача по окончании: участникам 90% (мутация слуха для событий — как
в v1, слух «чуть старше» правды); зевакам в радиусе 3 м — `10%·(1−d/3)`.
Визуал: «💬» над говорящими. Болтающие стоят в проходе — источник микропробок.

## 4. Инспектор агента (ui/inspector.js)

Клик по агенту (приоритет у табло, если ближе 2 м) → HTML-панель, живое
обновление: пресет; активность + топ-3 utility со значениями; полоски
stress/fatigue/boredom/phoneItch; параметры (mass, agility, politeness,
sociability, stubborn, personalSpace, conformity); знания (POI знает/всего,
вера о концерте vs правда с подсветкой расхождения, jamMarks); текущая цель и
режим поля (clear/smart/нет). Выбранный — белое кольцо + линия к цели.
Клик в пустоту/Esc — закрыть.

## 5. Очереди с деградацией (sim/queue.js)

POI с `service: {rate, queueDir}`: точка обслуживания, темп (1 чел / N игровых
сек), якорь и направление линии очереди.

- Прибытие с целью=POI → занять слот → активность `queue`, цель = якорь +
  index·0.6 м, шарканье вперёд при обслуживании головы.
- **Слом**: на think-тике в очереди: `stress > порога ИЛИ плотность у головы >
  порога ИЛИ slot > L` → `mobbing`: цель = точка обслуживания напрямую.
- Толпа у окна (плотность > порога): темп × 0.4 и обслуживается случайный
  ближний вместо головы → отстоявшие получают всплеск стресса
  (несправедливость) → лавина дезертирств.
- Обслуженный: сброс стресса/скуки («купил!»), уходит к новому POI.
- Восстановление: толпа рассосалась → новые приходящие снова встают в слоты.

Future (после джама): карточка табло «очередь работает» как успокоительное.

## 5.5 Приток и отток агентов

Как на настоящей выставке — население дышит:

- **Приток**: постоянный ручеёк с входов (главный + 2 боковых): новый агент
  каждые ~1–2 реальные сек (случайный вход, случайный пресет), плюс пики
  расписания (поезд = +80 разом к главному входу). Потолок населения ~700.
- **Отток**: новая активность `leave`. Utility растёт от «насыщения»
  (посещено POI ≥ личного порога 3–8) и усталости. Цель — ближайший вход
  (входы-выходы известны всем всегда), у выхода агент исчезает.
- Население видно в HUD (счётчик), баланс притока/оттока — ручки в tuning.

### Уточнение: знание о закрытых дверях (честность clearField)
Закрытие двери НЕ перестраивает общее clearField для всех (иначе все
магически узнают). Двери — именованные объекты; clearField существует в
вариантах по маске «какие двери агент ЗНАЕТ закрытыми» (дверей 1–2 → максимум
4 варианта, считаются лениво). Агент с пустой маской честно приходит к
закрытой двери, утыкается, узнаёт (глаза/табло/диалог → маска обновляется).
smartField всегда на актуальной топологии — обходчик смотрит по сторонам.

## 6. Оживление толпы

- **Dwell**: дойдя до несервисного POI → `browse` 4–10 с (мелкий дрейф),
  потом скука гонит к новому POI (взвешенный выбор по weight).
- **Alignment только в движении** (|v|>0.3): стоячие кластеры не засасывают.
- Wander-цели только в проходимых клетках.
- Wander speed 0.6 → 0.8.

## 7. Что умирает / появляется

Умирает: `sim/pathfinding.js`, вейпоинты/рёбра/adj в map, edge-беливы в
knowledge, осмос, стены-отрезки.
Появляется: `sim/flowfield.js` (сетка, Дейкстра, градиент, два набора полей),
`sim/dialogue.js`, `sim/queue.js`, `ui/inspector.js`, новый `data/map.js`.
Меняется: `agent.js` (knownPois, jamMarks, реакция на затор, новые параметры

`steering.js` (seek из градиента, alignment-gate), `draw.js` (блоки, пузыри).

## 8. Тесты (node)

- flowfield: градиент из любой проходимой клетки ведёт к POI; блок обтекается;
  закрытие проёма меняет маршрут; smartField обходит плотный кластер.
- dialogue: участники получают факт с ~90%, зевака ближе — чаще, дальше 3 м — 0.
- queue: порядок слотов; слом по стрессу; деградация темпа при толпе.
- grid: blocks → walkable корректно (узкие проходы проходимы).

## 9. Критерий приёмки v2 (глазами в браузере)

1. Толпа постоянно циркулирует по проходам между будками (нет залипших кластеров).
2. Никто не стоит лицом в стену дольше пары секунд.
3. Видны пары/группы с «💬», после — цветовая волна знания от них.
4. У фудкорта строится очередь; при наплыве ломается в ком и темп падает.
5. Упрямец ломится в затор, гибкий обходит, скучающий разворачивается
   (проверяемо через инспектор).
6. Инспектор открывается кликом и объясняет поведение агента.
