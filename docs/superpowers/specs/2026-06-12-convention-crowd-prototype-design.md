# Спека прототипа: «Ты — система навигации аниме-конвента»

Дата: 2026-06-12. Статус: дизайн для джам-прототипа (первые часы).

## 1. Видение и цель среза

Стратегия непрямого управления: игрок — навигационная система конвента. Люди —
автономные агенты, живущие в прошлом: они принимают решения по **своей устаревшей
копии знаний о мире**, а игрок управляет не людьми, а информацией.

**Цель прототипа (2–4 часа): доказать ядро-ощущение.** Толпа движется и пробкуется
эмерджентно, «волна знания» видна цветом, клик по табло ощутимо меняет потоки.
Если это не интересно наблюдать и трогать — остальное не имеет смысла.

**Технология:** HTML5 Canvas + ванильный JS (ES-модули, без сборщика).
Прототип — инструмент проверки геймдизайна; во второй половине джама — переезд
на Godot 4. Поэтому: симуляция отделена от рендера, весь контент и баланс — в
данных (`data/`), математика переносится в `_physics_process` дословно.

**Метрика игрока:** средний стресс толпы — одна полоска сверху. Без fail state
в прототипе.

### В срез НЕ входит (после джама / при переезде на Godot)
Доверие как ресурс, глобальные объявления, волонтёры-юниты, финальный
отчёт-история, лидеры мнений, служебные NPC, лагающие команды игрока,
неравномерное время, звук. Список хранится как питч «полной версии».

## 2. Движок толпы (ядро продукта)

Модель: **социальные силы (Helbing) + позиционное разрешение коллизий (PBD)**.
Стабильна (нет взрывов толпы), даёт эмерджентные пробки, арки в дверях, реки.

### Параметры агента

| Параметр | Смысл |
|---|---|
| `radius` | размер тела (большой косплеер = 2×) |
| `mass` | кто кого продавливает (сдвиг в PBD обратно пропорционален массе) |
| `maxSpeed` | крейсерская скорость |
| `agility` | скорость смены вектора (разгон + поворотливость); «ловкий волонтёр» |
| `personalSpace` | желаемая дистанция до чужих (личная зона) |
| `conformity` | склонность течь с толпой |
| `politeness` | готовность уступать (рефлекс) |
| `stress` | состояние; источник метрики игры |
| нужды: `fatigue`, `boredom`, `phoneItch` | топливо utility-выбора |

### Тик симуляции (фиксированный 30 Гц; рендер 60 FPS с интерполяцией)

1. **Spatial hash** (клетка ≈ 1 виртуальный метр). Через него: соседи, плотность,
   коллизии. O(N).
2. **Локальная плотность ρ** (соседи в радиусе ~2 м) → три кривые из `tuning.js`:
   `speedFactor(ρ)` ↓, `turnFactor(ρ)` ↓ (в давке не развернуться — проезжаешь
   мимо своей двери), `stressRate(ρ)` ↑.
3. **Желаемая скорость** = направление к вейпоинту × `maxSpeed` × `speedFactor`.
4. **Течение с толпой**: при ρ выше порога желаемая скорость смешивается со
   средней скоростью соседей; вес = `conformity` × плотность. Даёт реки и
   агентов, пронесённых мимо цели.
5. **Личная зона**: мягкое отталкивание от соседей внутри `personalSpace`.
6. **Интеграция**: скорость тянется к желаемой с темпом `agility × turnFactor(ρ)`.
   Быстрый неповоротливый — врезается.
7. **PBD-коллизии**: 2–3 итерации раздвигания пересекающихся кружков,
   масс-взвешенно. Узкая дверь + кружки = заторы сами собой.
8. **Стены**: проекция из стен после коллизий (стены всегда выигрывают).
9. **Стресс**: += от ρ сверх комфорта, контактов, «не продвигаюсь N секунд»,
   обманутого ожидания (слой знания).

**Рефлекс уступания** (каждый тик, поверх активности): среди соседей ищем
сходящихся с TTC < ~1 c; `priority = mass × speed × срочность`; если чужой
приоритет выше моего × `politeness` — боковой шаг + сброс скорости ~0.5 с.
Phone-агенты с perception = 0 рефлекс не выполняют (не видят).

Бюджет: 500 агентов × ~12 соседей — свободно на Canvas; потолок схемы на JS
~2–3 тыс.

## 3. Поведение: utility-мозг над стиринг-телом

Поведения **не пишут своё движение** — только перекручивают параметры конвейера.
Мозг тикает раз в 1–2 игровые секунды (фазы агентов сдвинуты), тело — каждый тик.

`score(активность) = личный_вес_агента × utility(нужды, контекст)`;
берём максимум; текущая активность получает ×1.3 (гистерезис).
Вектор личных весов = характер (зомби/планировщик/гуляка) — один механизм
вместо шести архетипов.

| Активность | Utility | Эффект на тело |
|---|---|---|
| **GoTo(цель)** | срочность по *его убеждению* о расписании × важность | стиринг к вейпоинтам |
| **Wander** | базовая константа | случайный POI, maxSpeed × 0.6; помечает пройденные рёбра как known (гуляние = изучение карты) |
| **Phone** | `phoneItch` | стоит/ползёт; **perception = 0** (не видит табло и не уступает), agility × 0.3, conformity × 2 |
| **Rest** | `fatigue` + `stress` × близость спокойной зоны | цель = зона с низкой ρ; стресс и усталость падают |
| **Lost** | включается событием: A* по убеждениям не нашёл путь / маршрут провалился N раз | см. §4 |

## 4. Слой знания (сердце игры)

Мир хранит правду; агент — **убеждения**: `belief = {значение, learnedAt}`.
Одна структура, три типа фактов.

### 4.1 Карта — частичный граф
По каждому ребру графа агент хранит `{known, passable, congestion, learnedAt}`
(битовые флаги + байт congestion; ~30 рёбер — дёшево).
**A* бежит по убеждениям**, стоимость ребра = `длина × (1 + штраф(congestion))`:

- Не знает ребро → пути не существует → идёт длинным.
- Считает закрытое открытым → приходит к двери → обновление глазами,
  стресс-всплеск, перезапуск A* от текущей точки.
- **Глаза** обновляют `congestion` всех рёбер в прямой видимости → видит забитый
  проход → маршрут подорожал → пересчёт → обход по известной альтернативе.
  Знающий больше страдает меньше; туристы ломятся в пробку.

A* перезапускается только при провале маршрута или новом факте о рёбрах.

### 4.2 Личная программа
`interests` (теги) + убеждения о событиях `{время, место, статус}`.
GoTo-utility — от своей копии. Спектр на входе: полный план → пустая программа
(«пришёл с другом», живёт на Wander и осмосе).

### 4.3 Факты и слухи
Источник фактов — системы мира (сток мерча падает от покупок, плотность зоны,
статусы расписания). **Генератор слухов = мутация при осмосе**: при передаче
факта агент→агент шанс ~10% исказить на ступень («мало» → «кончился»).
Одна вероятность в `tuning.js`.

### Каналы обновления знаний
1. **Табло** (рычаг игрока): клик → 3 контекстные карточки → агенты в радиусе
   видимости с perception > 0 копируют факт. Визуально — вспышка.
2. **Осмос**: соседние агенты медленно обмениваются фактами (шанс за тик
   контакта). Краска расползается сама.
3. **Глаза**: дойдя до места, агент узнаёт правду мгновенно; несовпадение с
   ожиданием = стресс-всплеск + статус «обманут» (фиолетовый).

### 4.4 Состояние Lost — генератор историй
Вход: A* по убеждениям вернул null или маршрут провалился N раз.
При входе: стресс-всплеск, пузырь «?!», капля стресса соседям (паника заразна),
тело стоит в потоке → PBD честно даёт локальную пробку.

Выход (по скорости): увидел табло (мгновенно) → спросил соседа (осмос-запрос,
секунды, если у соседа есть убеждение) → скачал карту в телефоне
(время = `база × (1 + k·локальная_плотность)` — **плотность и есть перегрузка
WiFi**, отдельной системы сети нет) → таймаут: плюнул, Wander.

Каскад заложен в формулы: пробка Lost-агента ↑ плотность → у соседей ↓ скорость,
↑ стресс, телефоны грузят дольше → новые Lost.

## 5. Карта и контент

`data/map.js`: 8–10 зон (прямоугольники: вход, холл, сцена, мерч, фудкорт,
туалеты, коридоры), стены (отрезки с проёмами), вейпоинты на дверях и
перекрёстках, граф рёбер (~20 узлов / ~30 рёбер), POI с вместимостью,
позиции табло.

`data/schedule.js`: 1–2 события для прототипа (поезд +200 человек к входу;
концерт в N игровых минут — миграция к сцене). Игровое время: часы на экране
игровые; масштаб времени — константа в tuning.

`data/messages.js`: карточки табло, контекстные к месту («К сцене через
восточный коридор →», «Зал X: заполнено», «Проход закрыт, обход →»).

## 6. Рендер и UI

Один Canvas, фиксированная камера (вся карта в экране).
Проход: зоны → стены → агенты → вспышки табло (кольцо, alpha-затухание) → UI.

**Цвет агента — двухканальный:**
- Заливка = возраст знания: зелёный → жёлтый → красный; фиолетовый = обманутый.
- Обводка = стресс: спокойный — нет, стрессующий пульсирует белым.

UI: игровые часы, полоска среднего стресса, карточки при клике на табло.

**Дебаг-оверлей (клавиша D) с первого дня**: тепловая карта плотности,
вейпоинты/граф, вектора скоростей, подсветка Lost. Это половина работы по
тюнингу эмерджентности.

## 7. Структура файлов

```
index.html
src/
  main.js            // цикл: fixed sim 30 Гц + render 60, интерполяция
  sim/
    agent.js         // параметры, нужды, utility-выбор активностей
    steering.js      // конвейер сил + PBD + рефлекс уступания
    spatialHash.js
    knowledge.js     // правда мира, убеждения, осмос, мутация слухов
    pathfinding.js   // A* по графу вейпоинтов по убеждениям агента
  render/
    draw.js
    debug.js
  ui/
    boards.js        // клик по табло, карточки
    hud.js           // часы, полоска стресса
  data/
    map.js
    schedule.js
    messages.js
    tuning.js        // ВСЕ коэффициенты баланса в одном объекте
```

Запуск: `python3 -m http.server` + браузер. Тестов на ядро математики
(spatial hash, A*, PBD-раздвигание) — минимум, через простой раннер в ноде.

## 8. Критерий готовности прототипа

Открыл в браузере и за 2–3 минуты наблюдения видно:
1. Толпа 300–500 агентов течёт, в узкой двери — честный затор.
2. Событие расписания запускает миграцию; цветовая волна знания расползается
   от табло и через осмос.
3. Клик по табло → карточка → вспышка → часть потока меняет маршрут.
4. Хотя бы один Lost-агент устроил локальную пробку, и она рассосалась
   (или переросла) сама.
5. Полоска стресса реагирует на действия игрока.

## 9. Заметки на переезд в Godot

- Вся математика §2–§4 — чистые функции от состояния; переносится в GDScript.
- `tuning.js` → Resource/JSON; `map.js` → сцена с Area2D-зонами.
- Канал «возраст знания → цвет» — шейдер/modulate на спрайтах.
- Контент (расписание, карточки, истории) пишется в данных уже сейчас и
  переезжает без изменений.
